`questions.js`에 새 퀴즈 문제를 **1개** 추가해 줘.

- 카테고리: `$1`
- 난이도: `$2`

## 1. 입력 확인 (하나라도 틀리면 추가하지 말고 사용법을 알려 줘)

- `$1`은 `CATEGORIES`(한국사, 과학, 지리, 문화·예술) 중 하나여야 한다. "문화예술"처럼 가운뎃점이 빠지면 `문화·예술`로 본다.
- `$2`는 `easy`, `medium`, `hard` 중 하나여야 한다. "쉬움/보통/어려움"으로 입력하면 각각 easy/medium/hard로 바꾼다.
- 사용법 예: `/quiz-add 과학 medium`

## 2. 기존 문제 확인

추가하기 전에 `questions.js`를 읽고 같은 카테고리 문제를 모두 확인한다. **이미 있는 문제와 같은 사실을 묻지 않도록** 주제를 고른다. (예: 이미 "태양계에서 가장 큰 행성"이 있으면 목성을 다시 묻지 않는다)

## 3. 형식 (기존 문제와 똑같이)

```js
  {
    id: 81,                       // 현재 가장 큰 id + 1
    category: "과학",
    difficulty: "medium",
    question: "…?",
    options: ["…", "…", "…", "…"], // 정확히 4개, 중복 없음
    correctAnswer: 2,             // 0~3
    explanation: "…."             // 정답 이유 1~2문장, "~입니다/했습니다" 체
  }
```

- 들여쓰기 2칸, 큰따옴표, 속성 순서는 위와 같게 한다.
- 배열의 마지막 문제 뒤(`];` 바로 앞)에 쉼표를 맞춰 넣는다.
- 정답 위치(`correctAnswer`)는 같은 카테고리에서 적게 쓰인 위치를 고른다.
- 오답 보기는 그럴듯하지만 분명히 틀린 것으로 한다. (같은 분류의 다른 대상)
- 난이도 기준: easy는 대부분 아는 상식, medium은 학교에서 배우는 수준, hard는 관심 있는 사람이 아는 수준.

## 4. 검증 가이드라인 (반드시 지키기 — `README.md` "문제 작성 기준")

1. **정답이 하나뿐인가?** 다르게 해석될 수 있으면 조건을 질문에 적는다. (면적 기준, 2024년 기준 등)
2. **최상급 표현에 기준이 있는가?** '가장', '최초', '최대' 등을 쓰면 측정 기준을 질문에 적는다.
3. **시간과 범위가 명확한가?** 바뀔 수 있는 정보는 시점을, 지역·분류는 범위를 적는다.
4. **교차 검증했는가?** 확실히 아는 사실만 쓴다. 출처마다 숫자가 다르거나 학설이 갈리는 내용은 문제로 내지 않는다. 숫자는 해설에 "약"을 붙이거나 기준 연도를 적는다.

## 5. 추가 후 확인

1. `node tests/test.js`를 실행해 모든 테스트가 통과하는지 확인한다. 실패하면 원인을 고친다.
2. 사용자에게 다음을 보여 준다.
   - 추가한 문제 전체 (질문, 보기, 정답, 해설)
   - 가이드라인 4항목 각각을 어떻게 지켰는지 한 줄씩
   - 확신이 덜한 부분이 있으면 숨기지 말고 적는다.
