# PRD: 할 일 관리 앱 (study_02)

- 작성일: 2026-10-14
- 상태: 승인됨 (구현 전)

## 1. 배경 및 목적

하루 10~20개 수준의 할 일을 관리하는 개인용 앱. 설치나 서버 없이 브라우저에서 바로 열리고, 새로고침해도 데이터가 사라지지 않아야 한다. 기술 스택은 순수 HTML/CSS/JavaScript로 한정한다 (프레임워크, 빌드 도구, 패키지 매니저 없음).

## 2. 범위

### 2.1 포함 기능

- 할 일 추가 / 수정 / 삭제
- 완료 체크 토글
- 카테고리 분류: 업무 / 개인 / 공부 (고정 3종, 사용자가 추가·수정 불가)
- 마감일 지정 (선택 입력, 비워두면 "날짜 없음")
- 마감일 기준 그룹 보기: 지남 / 오늘 / 이번 주 / 이후 / 날짜 없음
- 카테고리 필터 (전체 / 업무 / 개인 / 공부) — 보기만 거르고 진행률 집계에는 영향 없음
- "오늘 할 일" 진행률 바 (마감일 ≤ 오늘인 항목 기준)
- localStorage를 통한 데이터 영속화 (새로고침·브라우저 재시작에도 유지)

### 2.2 명시적 제외 (Out of Scope)

우선순위, 메모/상세 설명, 반복 할 일, 알림, 카테고리 직접 추가/편집, 드래그 정렬, 검색, 서버 동기화, 다중 기기 지원, 다중 사용자. 이들은 "하루 10~20개 개인용 관리"라는 목적에 비해 구현·유지 비용이 크므로 이번 범위에 넣지 않는다.

## 3. 데이터 모델

### 3.1 할 일 항목

```js
{
  id: "a1b2c3",            // crypto.randomUUID()
  title: "DB 3장 복습",     // 1~100자, 공백만은 거부
  category: "study",       // "work" | "personal" | "study"
  dueDate: "2026-10-14",   // "YYYY-MM-DD" 또는 null
  done: false,
  createdAt: "2026-10-14T01:20:00.000Z"
}
```

### 3.2 저장 형식

localStorage 키 `todoApp.v1` 하나에 아래 형태로 저장한다.

```js
{
  version: 1,
  todos: [ /* 할 일 항목 배열 */ ]
}
```

`version` 필드는 추후 데이터 구조가 바뀔 때 마이그레이션 분기점으로 쓰기 위해 처음부터 넣어둔다.

## 4. 화면 구성

```
┌──────────────────────────────────────────┐
│  할 일 관리            2026년 10월 14일   │
├──────────────────────────────────────────┤
│  오늘 할 일  ██████░░░░   6/10 (60%)     │
├──────────────────────────────────────────┤
│  [ 할 일 입력...  ] [공부▾] [10/14] [추가]│
├──────────────────────────────────────────┤
│  전체 | 업무 | 개인 | 공부                │
├──────────────────────────────────────────┤
│  지남 ⚠                                   │
│   ☐ 보고서 제출        업무  10/12  ✏ ✕  │
│  오늘                                     │
│   ☑ ̶장보기̶              개인  10/14  ✏ ✕  │
│   ☐ DB 3장 복습        공부  10/14  ✏ ✕  │
│  이번 주                                  │
│   ☐ 치과 예약          개인  10/17  ✏ ✕  │
│  이후 / 날짜 없음                          │
└──────────────────────────────────────────┘
```

### 4.1 그룹 규칙

- 그룹: 지남 / 오늘 / 이번 주(오늘 제외, 이번 주 일요일까지) / 이후 / 날짜 없음.
- 항목이 하나도 없는 그룹은 헤더까지 숨긴다.
- 그룹 내부 정렬은 **추가한 순서 고정**. 완료 체크해도 자리가 바뀌지 않는다.

### 4.2 완료 항목 표시

완료 체크한 항목은 목록에서 제거되거나 하단으로 이동하지 않고, **그 자리에서 취소선 + 흐림 처리**로만 표시한다.

### 4.3 카테고리 필터

필터 탭(전체/업무/개인/공부)은 화면에 보이는 항목만 거르며, 상단 진행률 숫자는 필터 상태와 무관하게 항상 전체 데이터 기준으로 계산한다.

### 4.4 수정/삭제

- 수정: ✏ 클릭 → 해당 행이 편집 모드로 전환(제목·카테고리·마감일 모두 수정 가능) → 저장/취소 버튼. 동시에 한 행만 편집 가능.
- 삭제: ✕ 클릭 → `confirm()` 확인 1회 → 삭제.

## 5. 진행률 계산

- **대상**: `dueDate !== null && dueDate <= 오늘` 인 할 일만 분모에 포함한다.
- **분자**: 대상 중 `done === true` 인 항목 수.
- **표시**: `진행률 바 + "n/m (p%)"` 형태.
- **분모가 0일 때**: 바를 비우고 "오늘 할 일이 없습니다" 문구로 대체 (0으로 나누기 방지).

## 6. 모듈 구조

```
study_02/
├─ index.html      구조 + <script> 태그 4개 (file:// 그대로 동작)
├─ style.css
└─ js/
   ├─ storage.js    localStorage 읽기/쓰기, 손상 데이터 방어
   ├─ todos.js      추가·수정·삭제·토글, 그룹 분류, 진행률 계산 (순수 함수)
   ├─ render.js     상태를 받아 DOM 그리기 (상태를 바꾸지 않음)
   └─ app.js        상태 보유, 이벤트 연결, 위 세 모듈 조립
```

ES 모듈(`import`/`export`)은 쓰지 않는다 — 로컬 서버 없이 더블클릭으로 바로 열려야 하기 때문. 대신 `index.html`에서 일반 `<script>` 태그로 생성 순서대로 로드한다.

### 6.1 데이터 흐름

```
사용자 이벤트 → todos.js 순수 함수로 새 배열 계산
            → app.js의 state 갱신 → storage.save() → render.js 전체 재렌더
```

부분 DOM 갱신(diff)은 하지 않는다. 항목 10~20개 규모에서는 전체 재렌더가 체감되지 않고, "상태가 바뀌면 화면은 항상 상태를 그대로 반영한다"는 단일 규칙을 유지하는 편이 버그 발생 여지를 줄인다.

`todos.js`는 DOM과 localStorage를 알지 못한다. 날짜 경계 계산·진행률 계산 같은 로직을 화면 없이 그대로 테스트하기 위함이다.

## 7. 에러 처리

| 상황 | 동작 |
|---|---|
| 제목이 빈칸/공백만 | 추가 거부, 입력창 테두리 강조 + 안내 문구 |
| 제목 100자 초과 | `maxlength` 속성으로 입력 자체를 제한 |
| localStorage 데이터 파싱 실패 (JSON 손상) | 빈 목록으로 시작 + 상단 경고 배너. 사용자가 인지하기 전까지 기존 데이터를 덮어쓰지 않음 |
| 저장된 항목 중 일부가 필수 필드 누락/형식 오류 | 그 항목만 버리고 나머지는 정상 로드 |
| 저장 실패 (용량 초과, 시크릿 모드 등) | 경고 배너 표시, 앱은 메모리 상 상태로 계속 동작 (저장만 실패) |
| 잘못된 날짜 입력 | `<input type="date">` 사용으로 입력 단계에서 차단 |

## 8. 검증 방법

npm·빌드 도구 없이 "순수 JS" 제약을 지키는 선에서 아래로 검증한다.

- **`js/todos.test.html`**: `todos.js`의 순수 함수에 대한 assert 모음. 브라우저로 직접 열면 통과/실패 목록이 출력된다. 검증 대상: 날짜 경계(어제/오늘/내일/이번 주 일요일), 진행률 분모 0 처리, 공백 제목 거부, 그룹 분류 정확성.
- **수동 체크리스트**:
  - 할 일 추가 → 새로고침 → 데이터 유지 확인
  - 완료 토글 → 오늘 진행률 즉시 반영 확인
  - 편집 중 취소 → 원래 값으로 복원 확인
  - 삭제 확인창에서 취소 → 항목 유지 확인
  - 카테고리 필터 전환 → 진행률 숫자 불변 확인
  - localStorage 수동 손상 후 로드 → 경고 배너 + 빈 목록 또는 부분 로드 확인

## 9. 비기능 요구사항

- 외부 라이브러리·CDN 의존 없음.
- `file://` 프로토콜로 더블클릭 실행 가능 (로컬 서버 불필요).
- 코드/주석은 기존 프로젝트(study_01) 관례를 따라 영어로 작성, 변수명은 camelCase.
