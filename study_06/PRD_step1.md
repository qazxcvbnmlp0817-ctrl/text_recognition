# PRD 1단계: 냉장고 사진 재료 인식 (study_06)

- 작성일: 2026-10-29
- 상태: 초안 (구현 전)
- 전체 구성: **1단계 재료 인식** → 2단계 레시피 생성 (`PRD_step2.md`) → 3단계 프로필·레시피 저장 (`PRD_step3.md`)

## 1. 배경 및 목적

냉장고 사진 한 장으로 "지금 있는 재료로 뭘 해 먹을지"를 추천받는 웹 애플리케이션을 만든다. 1단계에서는 사용자가 올린 냉장고 사진에서 재료 목록을 뽑아내고, 사용자가 그 목록을 직접 고칠 수 있게 한다. 이 목록이 2단계 레시피 생성의 입력이 된다.

AI 호출은 OpenRouter API를 사용하며, 1단계 이미지 인식 모델은 **`google/gemma-4-31b-it:free`** (이미지 입력을 지원하는 무료 모델)이다.

## 2. 범위

### 2.1 포함 기능

- OpenRouter 연동 기반 마련 (API 키 관리, 서버 프록시, 공통 호출 함수) — 2·3단계에서 재사용
- 이미지 입력: 파일 선택, 드래그 앤 드롭, 모바일에서 카메라 촬영 (`<input type="file" accept="image/*" capture>`)
- 업로드 전 미리보기, 다른 사진으로 교체
- 브라우저에서 이미지 축소 후 전송 (긴 변 최대 1024px, JPEG 품질 0.8)
- Gemma 4 모델로 재료 인식 → 재료 목록(이름, 대략적인 양, 분류, 확신도) 표시
- 인식 결과 편집: 재료 삭제, 직접 추가, 이름 수정 (AI 인식은 틀릴 수 있으므로 필수)
- 로딩 상태, 에러 메시지, 다시 시도 버튼
- "레시피 추천받기" 버튼 (2단계로 넘어가는 자리만 만들어 두고, 1단계에서는 비활성 또는 편집된 목록을 콘솔/화면에 출력)

### 2.2 명시적 제외 (Out of Scope)

- 레시피 생성 (2단계), 사용자 프로필·저장 (3단계)
- 사진 여러 장 동시 인식 (냉장고 칸별 사진 등) — 후속 과제
- 유통기한 인식, 재료 위치(바운딩 박스) 표시
- HEIC 형식 직접 지원 (아이폰 기본 형식) — 브라우저가 변환하지 못하면 "JPG/PNG로 다시 올려 주세요" 안내
- 업로드한 사진의 서버 저장 (인식 후 바로 버림)

## 3. 기술 구성

### 3.1 왜 서버가 필요한가

OpenRouter API 키를 브라우저 코드에 넣으면 누구나 개발자 도구로 키를 볼 수 있다. 따라서 **작은 Node.js 서버가 키를 보관하고, 브라우저는 서버의 `/api/...`만 호출**한다. 이전 study_02·05처럼 `index.html`을 더블클릭해서 여는 방식은 이번에는 쓸 수 없다.

| 구분 | 선택 | 이유 |
|---|---|---|
| 서버 | Node.js 18+ + Express | 내장 `fetch` 사용 가능, 설정이 단순함 |
| 프런트엔드 | 순수 HTML/CSS/JavaScript | 이전 study와 같은 방식, 빌드 도구 없음 |
| 환경 변수 | `.env` + `dotenv` | API 키를 코드와 분리 |
| 이미지 전송 | base64 data URL을 JSON으로 전송 | 브라우저에서 축소하면 1MB 안팎이라 별도 업로드 라이브러리(multer) 불필요 |

## 4. OpenRouter 연동

### 4.1 요청 형식

- 엔드포인트: `POST https://openrouter.ai/api/v1/chat/completions` (OpenAI 호환 형식)
- 헤더: `Authorization: Bearer <키>`, `Content-Type: application/json`, 선택으로 `HTTP-Referer`, `X-Title` (OpenRouter 대시보드에 앱 이름 표시용)
- 이미지는 `content` 배열에 `image_url`로 넣는다.

```js
{
  model: process.env.VISION_MODEL,
  messages: [
    { role: "system", content: RECOGNIZE_SYSTEM_PROMPT },
    {
      role: "user",
      content: [
        { type: "text", text: "이 냉장고 사진에 있는 식재료를 JSON으로 알려줘." },
        { type: "image_url", image_url: { url: "data:image/jpeg;base64,..." } }
      ]
    }
  ],
  temperature: 0.2
}
```

### 4.2 공통 호출 함수 (`lib/openrouter.js`)

```js
async function chatCompletion({ model, messages, temperature, timeoutMs }) -> string
```

- 응답의 `choices[0].message.content` 문자열을 돌려준다.
- `AbortController`로 타임아웃 처리 (1단계 기본 60초).
- HTTP 상태별로 의미 있는 에러로 바꿔 던진다 (7장 참고).
- 2단계 레시피 생성도 이 함수를 그대로 쓴다.

### 4.3 무료 모델 사용 시 주의

- 무료 모델은 분당·하루 요청 수 제한이 있다. 정확한 한도는 OpenRouter 문서와 계정 상태(크레딧 보유 여부)에 따라 다르므로 구현 시점에 확인한다.
- 사용자가 많이 몰리면 응답이 느리거나 `429`가 날 수 있다. 2026-10-29 시험 호출에서도 `google/gemma-4-31b-it:free`가 "temporarily rate-limited upstream"(제공사 쪽 일시 한도)으로 `429`를 돌려준 적이 있다.
  - **대체 모델**: `VISION_FALLBACK_MODELS`(기본 `nvidia/nemotron-3.5-super-vl:free`)를 두고, 1순위 모델이 `429`·모델 오류면 기다리지 않고 바로 대체 모델로 넘어간다. (구현 중 Gemma 4 31B·26B가 모두 제공사 한도에 계속 걸려서 추가)
  - 서버는 마지막 모델에서 `429`를 받으면 **2초, 5초 간격으로 최대 2회 자동 재시도**한다.
  - 그래도 실패하면 화면에 "잠시 후 다시 시도" 안내.
- 추론형 모델(Nemotron 등)은 생각하는 데 토큰을 다 써서 답이 비거나 잘릴 수 있으므로 요청에 `reasoning: { enabled: false }`를 넣는다.
- 무료 모델은 `response_format: json_object` 같은 구조화 출력 옵션을 지원하지 않을 수 있으므로, **프롬프트로 JSON을 요구하고 서버에서 파싱·검증**한다.

## 5. 재료 인식 프롬프트와 응답 형식

### 5.1 시스템 프롬프트 요지

- 너는 냉장고 사진에서 식재료를 찾는 도우미다.
- 눈에 보이는 **식재료만** 적는다. 그릇, 용기, 상표, 냉장고 부품은 제외한다.
- 무엇인지 확실하지 않으면 추측해서 적되 `confidence`를 `"low"`로 표시한다.
- 포장된 제품은 내용물 기준으로 적는다 (예: 우유팩 → 우유).
- 재료 이름은 한국어 일반 명칭으로 쓴다 (예: "대파", "계란", "두부").
- 아래 JSON 형식만 출력하고 다른 말은 하지 않는다.

### 5.2 응답 JSON 형식

```js
{
  "ingredients": [
    {
      "name": "계란",          // 한국어 일반 명칭, 필수
      "quantity": "약 6개",     // 대략적인 양, 모르면 null
      "category": "계란·유제품", // 아래 분류 중 하나
      "confidence": "high"     // "high" | "medium" | "low"
    }
  ],
  "notes": "아래 칸은 어두워서 잘 보이지 않음" // 모델이 남기는 참고 사항, 없으면 ""
}
```

분류 목록 (고정): `채소`, `과일`, `육류`, `해산물`, `계란·유제품`, `가공식품`, `소스·양념`, `음료`, `기타`

### 5.3 서버 측 검증 (`lib/parseJson.js`)

1. 응답 문자열에서 ```` ```json ... ``` ```` 코드 블록이 있으면 안쪽만 꺼낸다.
2. 첫 `{`부터 마지막 `}`까지 잘라 `JSON.parse` 한다.
3. `ingredients`가 배열이 아니면 실패로 본다.
4. 각 항목: `name`이 비어 있으면 버리고, `category`·`confidence`가 목록에 없으면 `"기타"`·`"medium"`으로 바꾼다.
5. 같은 이름이 중복되면 하나로 합친다.
6. 파싱에 실패하면 **같은 요청을 1회 재시도**하고, 그래도 실패하면 에러를 돌려준다.

## 6. API 명세 (서버)

### `POST /api/recognize`

요청:

```js
{ "image": "data:image/jpeg;base64,..." }
```

응답 (200):

```js
{
  "ingredients": [ /* 5.2 형식, 검증 완료 */ ],
  "notes": "",
  "model": "google/gemma-4-31b-it:free"
}
```

서버 검증:

- `image`가 `data:image/(jpeg|png|webp);base64,`로 시작하지 않으면 `400`
- 크기가 4MB를 넘으면 `413` (브라우저에서 축소하므로 정상적이면 넘지 않음)
- `express.json({ limit: "5mb" })`

## 7. 에러 처리

| 상황 | 서버 응답 | 화면 표시 |
|---|---|---|
| 이미지가 아닌 파일 선택 | (전송 안 함) | "이미지 파일(JPG, PNG, WEBP)만 올릴 수 있어요" |
| 브라우저가 이미지를 못 읽음 (HEIC 등) | (전송 안 함) | "이 형식은 지원하지 않아요. JPG나 PNG로 올려 주세요" |
| API 키 없음/잘못됨 (OpenRouter 401) | 500 `CONFIG_ERROR` | "서버 설정 문제로 인식할 수 없어요" (키 내용은 절대 노출하지 않음) |
| 요청 한도 초과 (429) | 429 `RATE_LIMITED` | "요청이 많아요. 잠시 후 다시 시도해 주세요" |
| 모델 사용 불가 (404 등) | 502 `MODEL_UNAVAILABLE` | "인식 모델을 지금 쓸 수 없어요" (서버 로그에 모델 ID 기록) |
| 60초 안에 응답 없음 | 504 `TIMEOUT` | "응답이 늦어요. 다시 시도해 주세요" |
| JSON 파싱 2회 실패 | 502 `BAD_MODEL_OUTPUT` | "결과를 읽지 못했어요. 다시 시도해 주세요" |
| 재료가 0개 | 200 (빈 배열) | "재료를 찾지 못했어요. 더 밝게, 가까이 찍어 보세요" + 직접 추가 입력창 |

모든 에러 응답 형식: `{ "error": { "code": "RATE_LIMITED", "message": "..." } }`

## 9. 검증 방법

- **단위 테스트** (`node --test`): `parseJson.js` — 코드 블록 감싼 응답, 앞뒤에 설명 문장이 붙은 응답, 잘못된 분류값, 중복 이름, 빈 이름, 완전히 깨진 응답
- **API 키 없이 테스트**: 환경 변수 `MOCK_AI=1`이면 `openrouter.js`가 고정된 예시 응답을 돌려주도록 해서 화면 흐름을 확인
- **수동 체크리스트**:
  - 실제 냉장고 사진 3장 이상으로 인식 → 주요 재료가 대부분 나오는지
  - 어둡거나 흐린 사진 → 에러 없이 `notes`나 빈 목록 안내가 나오는지
  - 큰 사진(10MB 이상) → 축소 후 정상 전송되는지
  - PDF 등 이미지 아닌 파일 → 안내 문구
  - `.env`에서 키를 지우고 실행 → 키가 노출되지 않는 에러 메시지
  - 휴대폰 브라우저에서 카메라 촬영 → 인식까지 동작
  - `git status`에 `.env`가 나타나지 않는지

## 10. 비기능 요구사항

- API 키는 서버 환경 변수에만 존재하며, 응답·로그·화면 어디에도 출력하지 않는다.
- 업로드 이미지는 메모리에서만 처리하고 디스크에 저장하지 않는다.
- 모바일 화면(폭 360px)에서 사용 가능해야 한다.
- 실행 방법: `npm install` → `.env` 작성 → `npm start` → `http://localhost:3000`

## 11. 열린 질문 / 후속 과제

- 이전에 만든 OpenRouter 연동 코드가 없어서 이 단계에서 새로 만든다. API 키는 `.env`에 저장 완료 (무료 등급 키, 2026-10-29 유효성 확인).
- 모델 변경 이력: 처음 계획한 `google/gemma-3-27b-it:free`는 2026-10-29 기준 OpenRouter 무료 목록에서 내려가 있어, 후속 모델인 `google/gemma-4-31b-it:free`(이미지 입력 지원)로 바꿨다.
- 인식 품질이 부족하거나 모델이 또 내려가면 `VISION_MODEL`만 바꾼다. 다른 무료 이미지 모델 후보: `google/gemma-4-26b-a4b-it:free`, `nvidia/nemotron-3.5-super-vl:free`.
- 사진 여러 장 인식, 유통기한 인식은 후속 과제로 둔다.
