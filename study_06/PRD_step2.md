- 작성일: 2026-10-29
- 상태: 초안 (구현 전)

## 1. 배경 및 목적

1단계에서 사용자가 확인·수정한 재료 목록을 바탕으로, **`nvidia/nemotron-3-ultra-550b-a55b:free`** 모델이 지금 만들 수 있는 레시피를 추천한다. 냉장고에 있는 재료를 최대한 활용하고, 없는 재료는 적게 쓰는 레시피를 우선한다.

## 2. 범위

### 2.1 포함 기능

- 1단계의 재료 목록(사용자가 편집한 최종본)을 입력으로 사용
- 추천 조건 선택: 인분(1~4인), 최대 조리 시간(15분/30분/60분/상관없음), 난이도(쉬움/보통/상관없음), 요리 종류(한식/양식/중식/일식/상관없음)
- 레시피 **3개** 추천 (카드 목록)
- 레시피별 표시: 이름, 한 줄 소개, 조리 시간, 난이도, 인분, 사용하는 냉장고 재료, **부족한 재료**, 조리 순서, 팁
- 레시피 상세 보기 (단계별 조리 순서)
- "다른 레시피 추천" (같은 조건, 이미 나온 레시피 제외 요청)
- 재료를 일부 빼고 다시 추천받기 (예: "계란은 아껴 두고 싶어요" → 재료 칩 선택 해제)

### 2.2 명시적 제외 (Out of Scope)

- 레시피 저장, 알레르기·식단 반영 (3단계에서 프로필과 함께)
- 레시피 이미지 생성
- 영양 성분·칼로리 계산 (AI 수치가 부정확할 가능성이 커서 제외)
- 스트리밍 출력 (JSON 전체가 와야 파싱 가능하므로 1차 구현에서는 한 번에 받음)
- 장보기 목록 만들기 — 후속 과제

## 4. 기본 양념 가정

집에 보통 있는 양념까지 "부족한 재료"로 표시하면 거의 모든 레시피가 부족한 재료투성이가 된다. 따라서 아래는 **있다고 가정**하고, 프롬프트에도 그대로 알려 준다.

> 소금, 후추, 설탕, 식용유, 간장, 식초, 다진 마늘, 참기름, 고춧가루, 물

화면의 조건 영역에 "기본 양념은 있다고 가정해요"라는 문구와 목록을 보여 준다. (3단계에서 프로필별로 바꿀 수 있게 확장)

## 5. 프롬프트 설계

### 5.1 시스템 프롬프트 요지

- 너는 가정 요리 레시피를 추천하는 요리사다.
- 사용자가 준 **냉장고 재료를 최대한 많이 쓰는** 레시피를 고른다.
- 냉장고에 없는 재료(기본 양념 제외)는 레시피당 **최대 2개**까지만 쓰고, 반드시 `missingIngredients`에 적는다.
- 조건(인분, 시간, 난이도, 요리 종류)을 지킨다.
- 실제로 존재하는 일반적인 요리를 추천하고, 조리 순서는 초보자도 따라 할 수 있게 구체적으로 쓴다 (불 세기, 시간 포함).
- 세 레시피는 서로 다른 요리여야 한다.
- 아래 JSON 형식만 출력한다.

### 5.2 사용자 메시지 예시

```
냉장고 재료: 대파, 양파, 당근, 돼지고기 앞다리살(약 300g), 계란(약 6개), 두부
기본 양념(있다고 가정): 소금, 후추, 설탕, 식용유, 간장, 식초, 다진 마늘, 참기름, 고춧가루
조건: 2인분, 30분 이내, 쉬움, 한식
제외할 레시피: 제육볶음 (이미 추천함)
레시피 3개를 추천해 줘.
```

### 5.3 응답 JSON 형식

```js
{
  "recipes": [
    {
      "title": "돼지고기 두부조림",
      "summary": "짭조름한 양념에 졸인 밥도둑 반찬",
      "cookingTimeMinutes": 25,
      "difficulty": "easy",              // "easy" | "medium" | "hard"
      "servings": 2,
      "cuisine": "한식",
      "usedIngredients": [               // 냉장고 재료 중 사용하는 것
        { "name": "두부", "amount": "1모" },
        { "name": "돼지고기 앞다리살", "amount": "200g" }
      ],
      "missingIngredients": [            // 냉장고에 없는 재료 (기본 양념 제외), 최대 2개
        { "name": "청양고추", "amount": "1개", "optional": true }
      ],
      "seasonings": ["간장 3큰술", "설탕 1큰술", "다진 마늘 1큰술"],
      "steps": [
        "두부는 1cm 두께로 썰어 키친타월로 물기를 뺀다.",
        "팬에 식용유를 두르고 중불에서 두부를 앞뒤로 3분씩 굽는다."
      ],
      "tips": "두부를 먼저 구우면 졸일 때 잘 부서지지 않아요."
    }
  ]
}
```

## 6. 검증 및 정리 (`lib/validateRecipe.js`)

모델 응답은 1단계와 같은 `parseJson.js`로 JSON을 꺼낸 뒤 아래를 확인한다.

1. `recipes`가 배열이고 1개 이상인지. 3개보다 많으면 앞의 3개만 쓴다.
2. 필수 필드: `title`, `steps`(1개 이상), `usedIngredients`. 없으면 그 레시피만 버린다.
3. `difficulty`가 목록에 없으면 `"medium"`, `cookingTimeMinutes`가 숫자가 아니면 `null` (화면에 "시간 정보 없음").
4. **부족한 재료 재계산**: 모델이 `usedIngredients`에 냉장고에 없는 재료를 넣는 경우가 있으므로, 서버에서 사용자 재료 목록·기본 양념과 비교해 없는 것은 `missingIngredients`로 옮긴다. 이름 비교는 공백 제거 후 포함 관계로 판단한다 (예: "돼지고기" ⊂ "돼지고기 앞다리살").
5. 재계산 후 부족한 재료가 3개 이상인 레시피는 목록 뒤로 보내고 "재료가 더 필요해요" 표시를 붙인다 (버리지는 않음).
6. 유효한 레시피가 0개면 1회 재시도, 그래도 0개면 에러.

## 7. API 명세 (서버)

### `POST /api/recipes`

요청:

```js
{
  "ingredients": ["대파", "양파", "돼지고기 앞다리살", "계란", "두부"], // 1~50개, 각 1~30자
  "options": {
    "servings": 2,              // 1~4
    "maxTimeMinutes": 30,       // 15 | 30 | 60 | null
    "difficulty": "easy",       // "easy" | "medium" | null
    "cuisine": "한식"            // "한식" | "양식" | "중식" | "일식" | null
  },
  "excludeTitles": ["제육볶음"]  // "다른 레시피 추천" 시 이미 나온 이름들, 최대 15개
}
```

응답 (200):

```js
{
  "recipes": [ /* 5.3 형식, 검증·정리 완료 */ ],
  "model": "nvidia/nemotron-3-ultra-550b-a55b:free"
}
```

- 재료가 0개거나 형식이 틀리면 `400`
- 프롬프트 주입 방지: 재료 이름은 길이 제한 + 줄바꿈 제거 후 프롬프트에 넣는다 (사용자가 재료 칸에 "앞의 지시를 무시해"를 적어도 재료 이름으로만 취급되도록).
- 타임아웃: 90초 (레시피 3개 JSON은 출력이 길어 1단계보다 오래 걸림)

에러 코드와 화면 문구는 1단계 7장의 표를 그대로 따른다.

## 8. 화면 구성

```
┌──────────────────────────────────────────┐
│  재료 (6)  [대파✓] [양파✓] [계란✓] ...    │
│  인분 [2▾]  시간 [30분▾]  난이도 [쉬움▾]   │
│  종류 [한식▾]                             │
│  ⓘ 기본 양념(소금, 간장 …)은 있다고 가정   │
│          [ 레시피 추천받기 ]               │
├──────────────────────────────────────────┤
│ ┌──────────────┐┌──────────────┐┌────────┐│
│ │돼지고기두부조림││ 계란말이     ││ 된장찌개││
│ │⏱25분 · 쉬움   ││⏱15분 · 쉬움  ││⏱30분   ││
│ │재료 5/5 보유  ││재료 3/3 보유 ││부족 1개 ││
│ │[자세히]       ││[자세히]      ││[자세히] ││
│ └──────────────┘└──────────────┘└────────┘│
│          [ 다른 레시피 추천 ]              │
└──────────────────────────────────────────┘
```

- 재료 칩은 체크로 켜고 끌 수 있다 (끈 재료는 이번 추천에서 제외).
- 카드에 "냉장고 재료 n개 사용", 부족한 재료가 있으면 개수와 이름을 강조 표시.
- 상세 화면: 재료(보유/부족 구분), 양념, 번호 매긴 조리 순서, 팁. 조리 순서는 단계마다 체크할 수 있어 요리하면서 따라가기 쉽게 한다 (체크 상태는 저장하지 않음).
- 생성 중: "레시피를 고민하는 중… (최대 1분 30초)" + 버튼 비활성화.
- "1단계로 돌아가기" 시 재료 목록과 사진은 유지한다.

## 9. 검증 방법

- **단위 테스트** (`node --test`):
  - `validateRecipe.js`: 필수 필드 누락, 잘못된 난이도, 4개 이상 반환, 부족한 재료 재계산(냉장고에 없는 재료가 `usedIngredients`에 섞인 경우), 기본 양념은 부족 재료로 잡지 않는지
  - `prompts/recipe.js`: 조건이 `null`일 때 "상관없음" 처리, 재료 이름의 줄바꿈 제거, `excludeTitles` 포함 여부
- **모의 응답**: `MOCK_AI=1`이면 고정 레시피 3개 반환 → 화면 흐름 확인
- **수동 체크리스트**:
  - 1단계에서 인식한 재료로 바로 추천 → 레시피 3개가 서로 다른 요리인지
  - 조건(15분, 쉬움)이 결과에 반영되는지
  - "다른 레시피 추천" → 이전 레시피와 겹치지 않는지
  - 재료 2~3개뿐일 때 → 에러 없이 간단한 레시피 또는 부족 재료 표시
  - 냉장고에 없는 재료가 "보유"로 잘못 표시되지 않는지
  - 모바일 폭에서 카드가 세로로 쌓이는지

## 10. 비기능 요구사항

- API 키·모델 원본 응답은 브라우저로 보내지 않는다 (검증된 JSON만 전달).
- 모델 원본 응답은 파싱 실패 시에만 서버 콘솔에 앞부분 500자까지 기록 (디버깅용).
- 레시피 내용은 AI가 생성한 것임을 화면 하단에 표시: "AI가 만든 레시피예요. 조리 시간과 양은 상황에 맞게 조절하세요."

## 11. 열린 질문 / 후속 과제

- 모델 변경 이력: 처음 계획한 `deepseek/deepseek-chat-v3.1:free`는 2026-10-29 기준 무료 목록에서 내려가 있어 `nvidia/nemotron-3-ultra-550b-a55b:free`로 바꿨다. 같은 날 시험 호출에서 한국어 레시피를 JSON 형식으로 약 2초 만에 정상 반환했다.
- 이 모델도 내려가면 `RECIPE_MODEL`만 바꿔 다른 무료 모델(예: `google/gemma-4-31b-it:free`)로 대체한다. 유료로 바꿔도 된다면 원래 계획한 `deepseek/deepseek-chat-v3.1`(100만 토큰당 약 0.25달러, 크레딧 충전 필요)을 쓸 수 있다.
- 무료 모델 응답이 느린 경우(1분 이상) 스트리밍 출력 도입을 검토한다.
- 장보기 목록(부족한 재료 모아 보기)은 3단계 이후 후속 과제.

## 12. 구현 메모 (2026-10-29)

- 레시피 모델도 대체 모델을 둔다: `RECIPE_FALLBACK_MODELS`(기본 `google/gemma-4-31b-it:free`). 1단계와 같은 규칙으로 동작한다.
- 모델이 조리 순서 앞에 "1.", "2)" 같은 번호를 붙여 화면 번호와 겹치는 경우가 있어, 검증 단계에서 앞 번호를 지운다.
- 실제 호출 기준 레시피 생성은 30~60초 걸렸다 (테스트 이미지, Nemotron 3 Ultra).
